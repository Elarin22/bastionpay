[BastionPay 보안 관제 프로젝트 발표 대본: K1 웹 스캐너 및 K3 Suricata IDS 경보 폭주 시나리오]

안녕하십니까, 이번 세션에서는 저희 BastionPay 보안 인프라의 침해 탐지 및 SOAR 자동 대응 체계 중,
외부 정찰 공격을 탐지하는 'K1 웹 스캐너 탐지'와 지능형 웹 공격을 감시하는 'K3 Suricata IDS 경보 폭주 탐지' 시나리오에 대해 발표하겠습니다.

========================================================================================
1. [K1] 웹 디렉터리 스캐너 탐지 시나리오 (발표 시간: 약 1분 30초)
========================================================================================

"먼저 K1 시나리오입니다. 공격자는 시스템 침투 전 단계인 정찰(Reconnaissance)을 위해 Gobuster나 Nikto 같은 도구를 이용해 관리자 페이지나 백업 파일 등 취약한 숨김 경로를 무차별 대입 스캔합니다.

저희 BastionPay 백엔드는 스프링 시큐리티를 통해 인증되지 않은 사용자가 미인가 경로를 찌르면 즉시 HTTP 401을 반환하며 'AUTHENTICATION_REQUIRED'라는 보안 이벤트를 파일비트로 전송합니다.

여기서 핵심적인 탐지 설계 포인트가 있습니다.
정상적인 사용자도 세션이 만료되면 401 오류를 낼 수 있습니다. 하지만 정상 사용자는 서너 개의 정해진 페이지만 반복 접근합니다.
따라서 저희는 단순한 요청 횟수(count)가 아니라, Graylog의 카디널리티(card) 집계 함수를 적용하여 '2분 내에 서로 다른 고유 경로 15개 이상'에서 401을 유발한 출발지 IP만 정밀하게 웹 스캐너 공격자로 식별하도록 설계했습니다.

(시연 또는 캡처 화면 설명)
실제 칼리 리눅스에서 16개의 가상 경로 단어장으로 Gobuster 스캔을 시도했을 때, Graylog가 고유 경로 16개를 즉시 인식하여 K1 이벤트를 발생시키고, n8n을 거쳐 BastionPay 관리자 대시보드와 디스코드 보안 채널에 실시간으로 인시던트 티켓이 발급되는 것을 검증 완료했습니다."


========================================================================================
2. [K3] Suricata IDS 경보 폭주 탐지 시나리오 (발표 시간: 약 2분)
========================================================================================

"다음은 네트워크 계층에서 고도화된 웹 취약점 공격을 탐지하는 K3 시나리오입니다.

공격자가 애플리케이션의 취약점을 노리고 SQL Injection, Path Traversal, XSS 페이로드를 집중적으로 쏟아부을 때, 네트워크 트래픽을 실시간 감시하는 오픈소스 NIDS인 Suricata가 ET-Open 시그니처와 매칭하여 'ids-alert' 경보를 발생시킵니다.
저희 Graylog는 30초 내에 동일한 출발지 IP에서 IDS 경보가 5건 이상 폭주할 경우, 이를 단순 오탐이 아닌 심각한 능동적 공격으로 판단하고 HIGH 심각도의 인시던트를 발동합니다.

여기서 저희 팀이 실제 환경을 구축하며 마주했던 중요한 네트워크 보안 이슈와 해결 방안을 공유해 드리고자 합니다.
현재 저희 BastionPay 웹 서버는 통신 보안을 위해 HTTPS(TLS 443 포트) 암호화를 기본 적용하고 있습니다.
네트워크 IDS는 트래픽이 암호화되어 있으면 페이로드 내부의 SQL 구문이나 악성 스크립트를 직접 복호화해서 보지 못하는 기술적 한계가 존재합니다.

따라서 저희는 이 시나리오를 2단계로 나누어 철저히 검증했습니다.
첫째, 실제 웹 취약점 페이로드를 웹 서버로 전송하여 백엔드 자체 방어 및 응답 코드를 확인했습니다.
둘째, 네트워크 암호화 환경에서의 센서 가시성 한계를 극복하고 SIEM과 SOAR의 자동화 파이프라인 무결성을 엄밀히 입증하기 위해, 업계 표준 로그 규격인 GELF(Graylog Extended Log Format) UDP 패킷으로 가상 공격자 IP의 Suricata 경보 5건을 직접 주입하는 방식으로 테스트했습니다.

그 결과, Graylog가 30초 내 5건의 IDS 경보를 정확히 집계하여 즉시 n8n 웹훅을 호출하고, n8n은 인시던트 티켓 생성과 동시에 심각도에 따라 공격자 IP 차단(IP_BLOCKED)까지 자동으로 수행하는 진정한 의미의 SOAR(보안 오케스트레이션 및 자동 대응) 흐름을 성공적으로 완주했습니다."

3. 맺음말 및 질의응답 대비 (발표 시간: 약 30초)
========================================================================================

"요약하자면, K1은 애플리케이션 로그의 '경로 다양도' 기반 정찰 탐지,
K3는 네트워크 NIDS와 SIEM/SOAR의 결합을 통한 '시그니처 임계치 초과 공격' 탐지 및 능동 차단입니다.
이상으로 K1, K3 취약점 점검 및 탐지 자동화 시연 발표를 마치겠습니다. 경청해 주셔서 감사합니다."
