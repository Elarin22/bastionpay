BastionPay는 오픈뱅킹 테스트베드와 자체 원장 기반 가상계좌를 한곳에 모은 교육용 금융 서비스입니다. 설계의 모든 단계에서 보안을 먼저 정합니다.

생활비 계좌

110-****-**4821

잔액 ₩1,250,000

거래 내역 예시
일시내용금액거래 후 잔액
10.18 09:12입금+1,500,0001,500,000

10.18 18:03이체−50,0001,250,000

기록은 수정하거나 지우지 않고, 정정은 반대 거래로 남깁니다.

실서비스가 아니기에,
보안을 끝까지 보여 줄 수 있습니다.

오픈뱅킹 테스트베드(가짜 은행)로 계좌를 조회하고, 자체 원장으로 가상계좌 입출금과 이체를 처리합니다. 모든 구성요소는 로컬에서 동작하며, 로그인부터 이체까지 요청마다 어떤 방어선이 작동하는지 직접 확인하는 것이 목적입니다.

인증은 HttpOnly 쿠키의 JWT로 처리하고, 보안 이벤트는 구조화 로그로 남겨 보안 관제 도구로 보냅니다.

주요 기능

  • 오픈뱅킹 계좌 연동

    사용자 인증을 마치면 등록된 계좌 목록과 잔액을 테스트베드 API로 조회합니다. 화면에는 계좌번호를 서버에서 마스킹한 값만 전달합니다.

    예시 데이터

    • 테스트 은행 A1002-***-**5678
    • 테스트 은행 B3021-***-**0934

  • 가상계좌와 불변 원장

    가상계좌를 발급하고 입금, 출금, 계좌 간 이체를 원장에 기록합니다. 금액은 BigDecimal로 다루고, 차변과 대변의 합이 맞는지 항상 검증할 수 있습니다.

    예시 데이터

    • 출금 · 생활비 계좌−200,000
    • 입금 · 저축 계좌+200,000
    • 합계0

  • 보안 중심 설계

    토큰은 쿠키에 담아 스크립트가 읽지 못하게 하고, 이체는 멱등키로 중복을 막습니다. 로그인 실패나 토큰 재사용 같은 이벤트는 로그로 남겨 탐지와 대응 자동화로 이어집니다.

    • HttpOnly 쿠키
    • SameSite
    • CSRF 방어
    • Refresh Rotation
    • 멱등키
    • 보안 이벤트 로그
